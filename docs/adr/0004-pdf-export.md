# ADR 0004：共享打印渲染与 PDF 输出

- 状态：已接受
- 决策日期：2026-08-15
- 更新日期：2026-08-16

## 背景

自由画布、裁剪、旋转、滤镜、蒙版和主题会同时影响编辑、缩略图、预览与打印。如果分别实现排版，屏幕结果与输出文件会持续漂移。桌面端和浏览器端又具有不同的导出能力。

## 决策

- 编辑画布、页面缩略图、整册预览和打印统一复用 `AlbumPageView` / `BlockView` 与 `AlbumDocument`，三类 Block 不维护导出专用分支。
- 只有导出对话框存在时才挂载共享 `PrintBook`，避免日常编辑常驻整册高分辨率 DOM。
- 桌面端等待 `document.fonts.ready` 和打印树内全部图片 decode 完成，再调用 Electron `printToPDF`。
- PDF 页面宽高从项目唯一 `PageSpec` 换算为英寸，支持 A4 横向、12 寸方形和 16:9；保持零边距并打印背景。
- 主进程先写入目标目录中的 `.partial` 文件，成功后原子改名，避免将中断写入伪装成完成文件。
- 桌面 E2E 同时验证输出文件头与三种预设的实际 PDF `MediaBox`；生产写入路径只以 `printToPDF` 成功、文件写入和原子改名为完成条件。
- 浏览器端调用 `window.print()`，由浏览器/系统打印对话框决定保存或打印，不模拟桌面文件系统 API。

## 结果

- 所有输出表面共享同一页面模型与图片效果，减少视觉漂移。
- 桌面端具备与项目物理尺寸一致的 PDF 文件流程，浏览器端保持轻量且无需 Electron。
- 长相册导出会在短时间内挂载完整打印树，仍需用真实大图和长页数样本持续观察内存峰值。
- Chromium 开始打印后没有可靠的逐页进度或安全强制取消能力，界面只展示真实阶段，不伪造百分比。
