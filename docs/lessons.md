# 项目经验

## 2026-08-15：参考项目不等于兼容目标

- 用户说明旧项目只用于参考时，不默认保留 importer、迁移器、旧 schema 或旧布局分支。
- 在计划中明确询问兼容范围；用户确认全新格式后，只维护一个权威文档模型并删除所有相关 fallback。
- 测试应保护当前产品的不变量，不应因为历史夹具继续扩大 legacy interface。

## 2026-08-16：几何交互测试不能只断言“发生变化”

- 缩放回归必须同时验证变化方向、变化幅度、像素宽高比和锚点；只检查 width/height 不等于旧值，会让坍缩、反向跳动和比例漂移全部漏过。
- 画布或父容器可缩放时，测试必须覆盖容器尺寸变化后的第一帧操作，并断言控制框与目标边界重新对齐。
- 几何库的 bounds 必须绑定到明确的 CSS 定位容器；画布位于滚动区时，还要覆盖 `scrollTop > 0` 的首帧操作，避免把可见视口误当成完整页面边界。

## 2026-08-16：尺寸预设与默认值必须分开确认

- 用户列出可选尺寸不等于确认默认尺寸；计划必须分别记录预设集合、每个预设的物理尺寸和当前默认项。
- 当用户后续修正默认项时，以最新明确决定为准，并同步检查新建项目、画布、打印图片和 PDF，不能只改选择界面。

## 2026-08-19：拖拽目标不等于实际插入位置

- 排序反馈必须绑定松手后会提交的插入间隙，不能把当前经过的目标项固定画成“插入到它前面”。
- 拖拽回归应同时断言提示线所在间隙与松手后的真实顺序；只检查拖拽时出现一条线，无法证明反馈正确。
- 页面缩略图尺寸需要按横向、纵向和方形 PageSpec 分别视觉检查，不能用横向页面的合适宽度推断纵向页面也合适。

## 2026-08-19：方案编号必须在资产写入前再次对齐

- 用户用 A1/A2/B1/B2 选择视觉候选时，把最新编号和候选文件名同时写进执行清单，并在覆盖正式资产前据此校验一次。
- 用户纠正候选编号后，立即停止旧候选的接入，清理仅由本次错误选择产生的临时成品，再从正确候选重新生成；不沿用旧稿的配色或造型假设。

## 2026-08-19：同一表面兼有点击与拖拽时必须保住点击语义

- 把按钮本体注册为拖拽 handle 时，不能使用立即激活的 PointerSensor；应为鼠标、笔和触控设置明确的长按阈值与移动容差，让短按仍然产生 click，快速滑动也不会误排序。
- 回归不能只调用合成 click：必须用真实 `mouse.down → 等待 → mouse.up` 证明短按会选择，再用超过阈值的 pointer 序列证明长按才拖动。
- 画布 Block 在窄屏用模态面板编辑时，已选 Block 的重复 pointerdown 不应重新打开面板，否则会截断后续拖拽；至少覆盖一个“选中、关闭面板、再次按住拖动”的真实断点场景。
